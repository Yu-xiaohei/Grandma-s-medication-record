## 2. 架构（已由用户拍板，不要再改）

- **前端**：Next.js 16.4.6 静态导出（`output: export`），托管在 **GitHub Pages**，子路径 `/Grandma-s-medication-record`。
- **后端**：**Cloudflare Workers + D1**（免费额度），无第三方依赖。
- **认证**：前台 4 位数字口令 → family token（7 天，存 localStorage）；后台 `Admin` + 密码 → admin token（12 小时滑动续期，响应头 `x-renew-token`）。
- **离线**：Service Worker 预缓存页面与静态资源；打卡先写 localStorage 队列，联网自动补传。
- **时区**：Worker 内部固定 `Asia/Shanghai`；前端用服务端时间做偏移校正，避免手机时间不准。

## 3. 功能现状（已实现，本地已验证）

### 3.1 前台（`/`）

- **主卡**：显示当前/下一项的时间、名称、全部条目（药/食/水）、备注（安全提醒）、倒计时；到点后显示「正好是现在」/「已经过去 X 分钟」。
- **今日列表**：16 个时间点，右侧徽标：已完成 / 未完成 / 已跳过 / 现在 / 已过时。
- **打卡抽屉**：每一条要单独勾选或点「暂缓」，**全部处理完才能点「完成」**；有进度条；可填备注；可选填心率/血压（后台开关）。
- **5 分钟规则**（`lib/rules.ts`）
  - 计划时间 **5 分钟以前或更早**点「完成」→ 二次确认「还没到时间，真的已经完成了吗？」
  - 计划时间前后 5 分钟内点「完成」→ 直接记录
  - 「未完成」按钮必须**过了计划时间 5 分钟**才可点；点击后二次确认，文案「确认这一项服用任务未完成吗」，取消按钮「我考虑一下」
  - 服务端兜底：family 角色在到点 5 分钟内提交 `missed` 会被拒（`too_early_missed`）
- **自动跳过（本轮新增，用户最后提的需求）**
  - 规则：上一项一直没点完成，且**距离下一项只剩 70% 的间隔**（即已过去 30%）时，自动记为未完成，主卡直接显示下一项
  - 例：11:50 → 12:30 间隔 40 分钟，12:02 触发；09:00 → 10:30 间隔 90 分钟，09:27 触发
  - 列表标「已跳过」，后台标「未完成 · 超过时间一直没打卡…」
  - **阈值可在后台「排程设置」里改**（限 30~95，默认 70）
  - 正在打卡抽屉里打开的那一项**不会被跳过**，避免勾到一半被打断
- **安全红线**：利尿看血压、美托洛尔看心率、喂完抬高床头 30°~45°，三条常驻卡片。
- **公告**：后台发布的公告以横幅形式出现在前台顶部，关闭后本机不再显示同一条（localStorage 记 id）。
- **口令门**：网页内置大键盘，4 位数字，同一设备 7 天免输；错误 8 次锁 15 分钟。
- **无障碍/适老**：按钮 ≥44px（实际主按钮 54px），支持 `prefers-reduced-motion`、`prefers-reduced-transparency`，iOS 液态玻璃风格可降级（低端机自动关透明）。

### 3.2 后台（`/admin/`）

四个页签：

1. **今天记录**：按时间列出今天 16 项，可补录/修改（逐条勾选、整项状态、备注）、可清除；已过切天时间则整页只读。
2. **排程设置**：
   - 切天时间 `dayStart`（默认 00:00，改 04:00 则凌晨 4 点前算前一天）
   - 自动跳过百分比 `autoSkipRemainPct`（30~95）
   - 记录心率/血压开关、前端口令开关、公告弹窗开关
   - 每一项的时间、名称、备注、条目（增删改）都能编辑
   - 口令与密码修改（新口令固定 4 位，新密码 ≥10 位）
   - 保存时只写「今天及以后」的 `day_plans` 快照，历史不变
3. **公告设置**：发布标题+正文，可设生效起止日期、归档、总开关。
4. **历史记录**：按日期倒序看记录，任务名按**当天当时的排程快照**解析（不是拿今天的排程反查）。

### 3.3 排程内容（照搬 Excel Sheet 1，已核对）

16 个时间点：07:30 / 08:00 / 08:40 / 09:00 / 10:30 / 11:50 / 12:30 / 13:00 / 14:00 / 15:15 / 16:30 / 18:00 / 18:30 / 19:30 / 20:30 / 22:00。

总量口径：营养液 150×6=900 ml、纯水 610 ml、蛋/菜/奶 300 ml(g)，合计 **1810 ml**。

## 6. 下一步：部署后端（主线任务）

> 前置：**必须由用户本人在终端跑一次 `wrangler login`**（会打开浏览器授权 Cloudflare）。这一步代理无法代劳，也不能用别的方式绕过。

### 6.1 登录并建库

```powershell
cd F:\Yuno-Develop\姥姥的用药计划表\worker
npx wrangler login
npx wrangler d1 create grandma_medication
```

把输出里的 `database_id` 回填到 `worker/wrangler.toml` 的 `database_id`（当前是占位符 `REPLACE_WITH_D1_ID`），然后提交。

### 6.2 生成三串密钥并写入

```powershell
# 每跑一次生成一串 32 字节随机 base64，共跑三次
$b = New-Object byte[] 32
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
[Convert]::ToBase64String($b)
```

```powershell
npx wrangler secret put TOKEN_SECRET
npx wrangler secret put PASSWORD_PEPPER
npx wrangler secret put SETUP_TOKEN      # 临时，初始化完要删
```

**密钥只进 Cloudflare，不要写进仓库、文档、聊天记录。**

### 6.3 建表并部署

```powershell
npx wrangler d1 execute grandma_medication --remote --file=src/schema.sql
npx wrangler deploy
```

记下输出的 Worker 地址，形如 `https://grandma-medication-api.<子域>.workers.dev`。
`wrangler.toml` 里的 `ALLOWED_ORIGINS` 已经是 `https://yu-xiaohei.github.io`；如果以后绑自定义域名，改成逗号分隔的多个来源。

### 6.4 初始化管理员（只跑一次）

```powershell
curl.exe -X POST https://grandma-medication-api.<子域>.workers.dev/api/setup `
  -H "content-type: application/json" `
  -H "x-setup-token: <SETUP_TOKEN>" `
  -d '{\"username\":\"Admin\",\"password\":\"Admin12345678\",\"pin\":\"0000\"}'
```

返回 `ok: true` 后：

```powershell
npx wrangler secret delete SETUP_TOKEN
```

（`/api/setup` 在 admins 表非空时会返回 409，天然只能用一次。）

### 6.5 把 Worker 地址接回前端


## 8. 已知限制与风险（下个会话要心里有数）

1. **自动跳过是「前端驱动」的**：只有在有人打开前台页面时才会计算并落库。如果整天没人打开页面，那天的项不会自动补成「未完成」。
   - 可选改进：在 `GET /api/bootstrap` 里对「今天已过项」做一次惰性回填。属于新功能，需用户同意后再做。
2. **口令只是软门槛**：family token 能做的只有读今日数据 + 打卡；但知道 4 位 PIN 的人都能拿到 token。8 次/15 分钟锁定，暴力枚举约需十余天。
   - 可选加强：PIN 改 6 位、降低尝试次数到 5 次/30 分钟，或启用 Cloudflare Access（免费版含 50 席位）。
3. **本地 D1 里有 14 条测试数据**（全部是「未完成」，备注「超过时间一直没打卡，自动记为未完成」）。上线用的是全新远程库，不受影响；本地若要重测可执行：
   `DELETE FROM records; DELETE FROM record_events;`
4. `worker/src/index.ts` 的 `admins.iterations` 列未使用（密码哈希是 HMAC-SHA256 + pepper，不是 PBKDF2，为的是留在 Workers 免费 CPU 额度内）。README 已注明这个取舍。
5. `lib/rules.ts` 的 `allItems()` 目前是死代码，留给将来「一键全部打勾」用。
6. 后台改 PIN 的输入框 `maxLength=4`，服务端允许 4~8 位，但 **Gate 只接受 4 位**，所以实际上只能是 4 位。
7. 部署脚本注释里 `NEXT_PUBLIC_BASE_PATH` 由 workflow 自动计算；绑自定义域名时需加 `BASE_PATH=/` 变量。
8. 仓库是 PUBLIC，Worker 地址公开可发现，所以 PIN 强度与限流是唯一屏障。
9. `.gitignore` 已排除：`.env.local`、`worker/.dev.vars`、`node_modules`、`out`、`.next`、`.agent-tmp`、`next-env.d.ts`、`tsconfig.tsbuildinfo`。

## 9. 待用户确认的问题（交付时一起问，不要逐个打断）

1. **「70%」的理解确认**：现在的实现是「距离下一项只剩 70% 的时间就开始跳过」（即已过 30% 间隔）。
   如果你想要的是「只剩 30% 才开始跳过」，把默认值改成 30 即可（后台也能改）。
2. 是否需要「自动跳过也由服务端回填」（即第 8 条第 1 点），这样即使没人打开页面，后台历史也完整。
3. PIN 是否升级为 6 位（更安全，但老人多记两位）。
